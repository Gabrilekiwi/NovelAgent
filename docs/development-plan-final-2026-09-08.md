## 1. 本轮交付目标

让作者在Windows本机使用已有作品完成“章意图 → 候选正文 → 审读编辑 → 事实检查 → 正式提交 → 下一章”，同时具备逐章审核和有限范围连续自动两种模式。异常可解释、草稿可保留、提交可恢复、费用可追溯。

### 已确定的用户选择

1. 稳定自用版，Windows本地单用户。
2. 逐章审核与连续自动在同一版本交付。逐章审核为默认模式。
3. 连续自动允许最多一个预算内自动修复周期；仍未通过则暂停并转人工。
4. 已有作品优先，完整从零建书引导后置。
5. 真实Provider调用和人工阅读独立安排。本文不授权新的付费调用；早期验证和最终连续验收分别限定范围与预算。

### 首版范围决策

| 旧书升级 | 优先保留book_id、正式历史和人工内容，通过经过验证的格式升级接入；不默认强制迁移为EA |

### T2：事实契约、身份、审核与质量策略

| 编号 | 交付物 | 验收 |
|---|---|---|
| T2.1 | 七类事实同源契约、必填字段、操作值、模型示例和本地校验；before值、数量和依赖由程序计算 | 七类混合样例可解析；重复、无来源数量、歧义顺序和被拒事件的依赖被拦截；本项不提前声称下章可读 |
| T2.2 | 角色/地点/物品的最小稳定身份声明、已有别名复用、基线缺失处理 | 同章新实体可引用；未知/重名/缺基线进入明确处理；接入T3.2后验证下章读回 |
| T2.3 | 作者接受、修改、拒绝、补充及显式批量决定；正文与事实对照界面 | 原始模型建议不被覆盖；作者补充独立记来源；改稿使旧证据/决定过期；无需编辑JSON |
| T2.4 | 可版本化的质量策略与离线样例结果 | 确定性阻断、语义风险、普通建议分开；每个语义问题附原文证据；误报、漏检和额外调用有记录 |

事实绑定规范化正文的修订、哈希和准确引用。作者原文编辑后不得沿用旧确认。正文有事实变化却未提取到时，不能把空集合默认为安全；逐章模式需作者明确确认或补充，自动模式需完成当前策略规定的检查。

审核界面优先展示事实变化、冲突与需要判断的项，同时可查看全部。不得把隐藏、默认勾选或未经操作的记录写成作者确认。首轮操作观察记录审核条目、修改/拒绝、重复操作及入口困难，不新增复杂遥测系统。

| T3.2 | 有限共享的准备、提交与核验服务；工作台提交预览和提交入口 | 幂等、过期拒绝、正式事务、崩溃恢复、凭证核验与DB索引重建通过；EA已有行为相关回归通过 |

**D1必须回答：** 人工初始设定与当前状态各自是什么；哪些字段随章节推进；冲突决定绑定哪个来源修订；来源后改如何失效；当前状态如何仅从项目权威资料重建。优先试验复用现有领域模型和项目内结构化受管内容，但不能直接把现有supporting字段当成权威，也不能静默降低人工设定优先级。

**D2支持边界：** B0是T0.1实际保存并能运行的升级前版本；首版明确验证B0与新版本，其他历史程序不在兼容保证内。用真实旧程序验证拒写，不能修改旧程序后再声称兼容通过。升级前处理或停止在途任务；不兼容任务保留查看和诊断证据，阻止在新代码下直接执行。不建设多版本并行运行器，也不凭一个commit字符串承诺旧任务可续跑。

保留book_id、既有正文与不可变历史。具体格式变更在隔离样本验证后写入D2；升级真实作品前需要T7.1备份、差异预览和有效Strict资格。隔离试验的合成资格不能冒充真实校准结果。代码回退必须匹配数据格式和快照；新格式已写入后不能只回退代码。

共享提交绑定项目、章号、最终正文和事实决定修订、上下文read-set、权威版本、幂等键。先规范化正文再核验引用；只提交下一未提交章。正文、状态、章游标及必要凭证进入既有正式事务，SQLite提交结果为索引；作者草稿等DB原生数据仍需数据库自身持久化与备份。

T3.2故障验收至少包含：双击产生一个逻辑提交；同幂等键换内容报冲突；改稿/手写来源变化/章号被占用时拒绝过期计划；提交标记前失败不推进，标记后失败完成原事务恢复；正文已提交但DB索引未更新时从凭证恢复，不再调用模型生成。

### T5：用量、金额和时间预算

| 编号 | 交付物 | 验收 |
|---|---|---|
| T5.1 | 每个物理attempt的阶段、模型/端点、用量与来源；actual/estimated/unknown费用展示 | 旧无依据零值显示未知而不改历史；失败和重放不漏记、不重复记 |
| T5.2 | 冻结单章价格与金额预留/结算；执行耗时与人工等待分离 | 超限在发请求前阻断；修复/提取/检查共用预算；恢复不清零；人工等待不触发模型执行超时 |
| T5.3 | 自动批次统一币种、单章与批次金额/调用/token上限 | 下一调用可能超限即暂停；缺可解释价格不启用金额受控自动批次；同批次修复计入总额 |

调用分类规则固定为：确定未发送或本地预算拒绝可释放金额预留；用量可解释时结算；已尝试但费用未知或调用状态未知时保留预留和原因。所有分类保留审计记录，不能仅凭普通网络/HTTP异常认定免费。价格按provider/endpoint/model冻结，不把兼容端点套用官方价；无汇率换算和自动账单核对。

时间分为累计主动执行、作者等待、端到端历时。现有900秒默认值只在核对适用范围后用于主动执行预算，不直接用作包含人工审稿的整章截止时间。执行区间持久化；未闭合且无法解释的区间在恢复时标未知并暂停处理，不能靠重启归零或把整段离线时间猜算成执行时间。

缺价格时逐章工程使用可明确的token/调用限制，但不能宣称金额止损。T8.1真实调用前必须完成所用单章路径的T5.2和保守费用预检；自动批次必须完成T5.3。周预算保留统计用途，执行止损以冻结的单章/批次预算为准。

### T6：连续自动与一次修复

| 编号 | 交付物 | 验收 |
|---|---|---|
| T6.1 | 有限章号批次、冻结章纲/模型/预算/策略、policy审核来源 | 正常三章依次提交；下一章在前章正式提交和readback后开始；与人工相同最终输入产生相同领域结果 |
| T6.2 | 持久化的一次修复周期、重新提取和重检 | 第二章首检失败修复通过后续写；修复失败则第三章零调用；修复中重启不新增一次额度 |
| T6.3 | 原位人工接管、明确继续批次、暂停/停止与恢复 | 作者可处理并继续原批次；重启零自动付费调用；作者稿不被自动覆盖；不确定调用不自动重发 |

三类检查的处置：

- 身份/基线未知、来源冲突、read-set变化、凭证损坏、事务未恢复、调用状态不确定、预算不足：直接暂停，不能让模型猜测后放行。
- 有具体正文证据且属于策略中已列明的格式/连贯性问题：允许一个预算内修复周期；通过全部最终检查才继续。
- 无事实或连贯性影响的一般文风建议：保留记录，可继续；不能据模糊评分无限修复。

周期开始前持久化消耗修复资格。修改正文后首版完整重提取、重检，不做“只处理受影响事实”的增量优化。检查失败不等于正文没问题；模型未发现问题也不等于已经证明没有遗漏，策略须由T8.0/T2.4样例及真实阅读检验。

自动接受记录`review_source=policy`、策略版本与批次授权；人工接受记录`author`。不伪造`author_confirmed=true`。模式切换只在章边界或暂停状态发生，新的付费继续操作需要已有有效授权。

### T7：保全、可写恢复与Windows发布

| 编号 | 交付物 | 验收 |
|---|---|---|
| T7.0 | 最小恢复试验和恢复决议D3 | 一个已提交章、一个作者草稿复制到同机新空目录；不改旧不可变历史，建立可验证的新物理绑定；重启后用假Provider提交下一章 |
| T7.1 | 升级前归档、目标作品可恢复备份、维护状态与预检清单 | 数据库与目标文件在受控停写期间取得一致快照；缺必要根或证据时不标记可恢复；失败现场仍可保存诊断归档 |
| T7.2 | 将D3方案用于最终新流程的完整恢复入口 | 正文、状态、作者草稿、批次位置、预算与凭证核验一致；恢复后零自动调用；可继续确定性下一章；损坏归档拒绝启用 |
| T7.3 | Windows发布检查、依赖锁、安装/升级/回退文档和CI | 干净Windows按文档启动；中文/空格路径、双击、重复启动、重启、匹配版本回退均通过 |

备份范围是**目标作品的可恢复备份**：目标书完整文件、必要runtime/模型调用与提交凭证、作者草稿、任务和预算、完整SQLite快照、非秘密运行配置、版本与文件哈希清单。复用整份SQLite快照避免未经验证的关系裁剪；其他登记作品没有随包恢复其文件，因此恢复实例中默认禁用且不得访问或调度这些作品。不能将此包称为“完整工作台备份”。

取得一致快照前进入维护状态，阻止新任务和编辑，等待已有写操作结束，按固定顺序取得所需锁；使用SQLite backup API并协调外部文件。活动调用、未恢复事务和未知外部根阻止可恢复认证，但可单独生成明确标注用途的诊断归档。归档预览显示范围与体积，排除凭据及.env，恢复时重新配置密钥。

D3必须解决旧path guard的device/inode等物理身份约束；不能仅改root字符串，也不能改旧manifest/hash来通过验证。恢复先只读核验，再建立有来源证明的新运行绑定；所有未提交准备计划失效并重新准备。旧作者草稿保留，新正文检查按新上下文重做，已提交结果只核验不再生成。

同机恢复交接必须覆盖同一book_id的原实例与恢复实例：采用本机作品级所有权约束，并在恢复启用时停用原注册的写入资格；锁的覆盖范围不能只跟随各自的数据目录。正常写入口在提交前校验当前资格，未完成交接时恢复副本只读。本轮不承诺阻止任意历史程序或其他机器上的手动副本写入。

只读解压、TXT导出或保存一个before-image都不能替代T7.2。若D3失败，保持资料保全与隔离试验，重新限定恢复实现方案；稳定版的可写恢复门槛不删除。

## 5. 独立验证与发布标准

### T8.0：现在即可准备的离线证据

使用已有正文、保存响应和合成材料，建立小型版本化检查集：七类混合事实、漏事实、身份歧义、数量变化、重复/连贯性缺陷和正常章节。真实材料只读取证，研发产物在隔离目录；记录每个样本来源与人工判定依据。测试集不冒充新模型效果评估，不从单章推断全书质量。

### T8.1：早期同模型配对验证

前提：T4.2、相关T5.2和T7.1完成；验证作品具备真实有效Strict/契约资格。用户独立明确Provider、金额上限和阅读安排后才调用。

先做有限Provider兼容检查及一章完整验证，再做三个配对章节任务。每对固定章意图和上下文材料、模型/端点及计费配置，分别采用作者手工管理同模型与工作台逐章流程；记录允许的调用/输出边界和实际总消耗。首轮集中比较逐章模式，不混入强制故障或自动接管样本。兼容检查如纳入配对，必须在运行前声明。

保留原稿与修改稿，阅读时隐藏来源、随机顺序；实际操作者无法盲化，记录操作顺序。统计章意图准备、正文编辑、事实核对、排错恢复等总主动时间，等待时间单列。正常重复操作也计入，不只记录编辑器停留时间。

早期通过方向：无严重事实缺陷；三对样本的人工九维均分及总体可用性汇总不低于对照；工作台三任务的总主动用时低于对照三任务之和；费用在授权范围内。同步报告每对差异，不用汇总掩盖严重个例。三个样本只用于发现方向和瓶颈，不证明长期稳定。30%节时是观察目标，不是已经由用户确定的硬门；若收益不清楚，明确记录结果并先改造成额外负担的环节。

没有本阶段授权时，完成样本、流程、计时表和预算预检即可继续独立工程；不得自动调用，也不得标记收益验证通过。

### 工程候选版

必须完成本版T0–T7的全部任务与T8.0，D1–D3有结论；目标旧书两模式闭环、七类事实冷读、Windows执行所有权、预算、一次修复、可写恢复和安装验证均通过。EA已有功能相关回归通过，但不要求新流程完整对等。

在T3.2完成、T6完整集成及最终发布候选点运行全套pytest与本地smoke；其他小任务运行相关检查即可。无新改动或未解决问题时不重复同一套测试。跳过项、平台限制与未做的真实验证单列。所有浏览器演练使用隔离DB/作品和确定性Provider，并查看实际页面、console、network及重启结果。

### T8.2：两模式正式连续生产验收

工程候选版通过后，独立安排本阶段预算与阅读。T8.1授权不能自动延伸至本阶段；缺少早期结果时先补T8.1，再决定是否启动长批次。

冻结代码、依赖、模型、端点、价格、预算、策略、章纲与评分口径。以当时最新正式状态准备经过验证的验收工作区，保留既有失败证据，不固定使用过时章号。十章逐章审核、十章连续自动分别计分；可按正常剧情顺序推进，但不能把前后两批当作严格模式因果对照，也不能合并声称二十章自动可靠。

| 指标 | 本版验收口径 |
|---|---|
| 正式完成 | 每批预定10章全部正式提交并readback；停滞、放弃、预算耗尽不能删掉或替换样本后算通过 |
| 首次通过 | 首次生产尝试中原始第一候选在正文修复或人工实质修改前通过规定检查的章数 / 预定10章，至少70%；首次生成失败或没有候选即不计首过，后续恢复不追改；模型/系统失败原因另列 |
| 严重问题 | 无严重事实缺陷、草稿丢失、重复逻辑提交、未解释内部错误或不确定调用自动重发 |
| 修复与接管 | 每章自动修复至多一次；自动批次至少8/10章无需额外人工接管完成，故障演练不混入该自然批次 |
| 人工质量 | 九维均分至少3.8，至少8/10章总体可用性不低于4；模型分与人工分分开；评分前固定锚点与严重缺陷定义 |
| 用时 | 保留原有编辑时间中位数≤20分钟、P90≤30分钟的目标，同时报告全部主动时间、原始逐章用时和最大值；小样本P90只作描述 |
| 连续性趋势 | 后3章人工均分相对前3章下降不超过0.3，并逐项阅读核对事实连续性；该差值不证明长期无退化 |
| 成本与收益 | 两批均不超冻结预算；配对验证的质量与主动时间收益成立；费用未知不能填零冒充达标 |

上述量化值作为本版沿用的工作验收标准，在开始真实批次前固定到记录；若需调整，只能用于随后新批次并说明依据，不能在看到结果后追改本批通过线。30%节时仍非硬门。

正式试验全程保留预定、启动、提交、失败、放弃数量及所有调用/主动时间。代码、模型、章纲等冻结条件改变时本批失效，原费用和失败仍保留；重新验收建新批次，不覆盖记录。常规人工审读不算异常接管，但全部计入主动时间。

**只有工程候选版和T8.1/T8.2均通过，才标记“稳定自用生产版”。** 未通过时按实际状态称工程候选版或待验版。

## 6. 额度中断与执行纪律

同一时间一个主攻实现任务，最多一个边界清楚的辅助审查。子任务以一次可核验的变更或试验为单位；表中子项若仍需跨多个改动面，开工前继续拆为独立验收步骤，不能把整个阶段作为一次长任务。

每次完成或中断前写入交接：当前任务/子步骤、实际commit与未提交文件、改动目的、运行命令及结果、未解决条件、下一条具体操作、进程/端口、模型调用与预算状态。只把已有退出结果的检查记为通过；源代码、诊断和测试证据可分别保存，不能因额度中断启动第二份任务或重发不确定调用。

恢复先读交接，再核对Git差异与活动进程；不重做已完成调查和无变化的测试。常规任务更新进度，不重新制定整份计划。只有新证据改变依赖、范围或验收时才修订本文件，并记录受影响任务及原因。
