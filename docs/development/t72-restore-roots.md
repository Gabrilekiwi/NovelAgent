# T7.2 新物理根与历史只读映射

日期：2026-09-14。该组件接续真实解包产物。完整数据库仍保持原字节，工作台启动仍被恢复意图阻止，**没有启用恢复实例或完成 T7.2 可写恢复**。

## 实现与边界

`workbench/backup_restore_roots.py::bind_restored_roots` 从磁盘读取复制计划、意图和完成凭据，再从原归档完整重验计划。内部位置规划可接受已经存在的容器，但必须额外核对容器物理身份、完整复制清单和逐文件内容；公开的恢复位置规划与实际解包入口仍要求新空位置。

绑定期间持有恢复数据目录的实际单实例锁。原根登记的字节以 base64 原样保存在容器外层 `root-binding.json`，并与原归档、复制凭据、计划和新物理根关联。只更新书内可变 `root_registry.json` 的物理路径、目录身份、已有运行锁身份、版本及时间；保留 registry ID 和 logical root UUID。缺少原先已准备的锁或目录时不能悄悄创建来补齐证据。

原 manifest、PathGuard、marker、回执、作者资料和运行证据不改写。验证旧 v1/v2 联合历史时，原绝对路径只作为证据坐标，实际资料从新书目录读取；原 registry 由已核验的原字节提供。随后调用**未经放宽的** `load_verified_reviewed_identity` 验证新位置的升级、事实状态和章节提交历史。普通 PathGuard 仍拒绝旧准备计划。

`root-binding.json` 必须先于可变登记更新落盘。重入只接受与原意图完全一致的物理根和原版/本次新版登记；其他内容拒绝。登记写入后若进程退出，可从原意图显式继续，原计划不会重新执行。归档退出校验、全副本核对与正常历史冷读完成后，才发布 `root-binding-done.json`。

这不是同机作品所有权交接：目前只拥有恢复数据目录锁；原作品的写资格尚未改变。没有修改 SQLite 目标登记、任务路径或草稿，没有接入恢复向导，也没有建立下一代 legacy 执行目录。完成凭据仍保持 `database_rebound=false`、`read_only_app_ready=false`、`ownership_handoff_completed=false`、`restored=false`、`write_activation_allowed=false` 和 `recoverable=false`。
