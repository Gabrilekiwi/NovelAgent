# T7.2：恢复副本旧任务隔离

日期：2026-09-15。状态：内部旧 workbench 任务隔离已验收，恢复副本仍只读。

## 目标与范围

归档中的 workbench 任务只能作为历史读取。完成恢复后也不能直接继续原任务、重新使用原执行契约，或让旧任务占据新任务队列。原配置、结果、错误、事件及其他作品数据必须保留。

内部 `RestoreJobPreparation` 依赖已完成的实际预算准备。它从原归档预测原根/数据库重绑定和任务隔离后的完整 SQL 摘要，再核对实际恢复副本。新增历史表保存每一条原任务完整 JSON 和摘要；所有导入任务的执行契约改为历史契约，未完成任务改为 cancelled，原终态保留。任务修改与历史表在同一 SQLite 事务提交。

历史事件、草稿、作品资料、预算文件、模型消费和机器交接代际不因本步骤改变。旧数据库绑定凭据也不改写；新的任务准备意图和完成回执单独记录后续限定变更。普通数据库绑定/预算准备入口不得将这次 SQL 变化自动认可为其原始状态。

## 验收要求

- 实际归档→物理恢复→根/数据库绑定→原资格撤销→原消费保存→预算准备→旧任务隔离。
- 含 queued、completed、cancelled、failed 的原任务，完整原行、事件、草稿及其他作品资料保留。
- 原任务执行契约检查拒绝续跑；恢复工作台仍只读，自动 worker 不启动，其他作品不可访问。
- 原目录不可用时可沿同一意图重复核验、显式续接；不补造缺失意图或完成凭据。
- 意图保存后、事务提交前（含已刷脏页）、提交后及完成回执后真实强退；原任务修改要么全部回滚，要么全部提交。
- 数据库出现额外修改、历史快照损坏、依赖凭据丢失或提交前变化时拒绝，不能自动修复或覆盖。
- 回退后原任务准备资格失效，恢复副本继续只读。
