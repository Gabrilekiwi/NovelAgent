# T7.1 预检、维护重启与控制入口

日期：2026-09-11。T7.1 仍在实施；完整目标作品归档、认证和可写恢复尚未完成。本文替代早期快照文档中“任意已持有事务可直接作为快照来源”的结论。

## 修正的两个缺口

只读复核确认：`create_app` 原先在维护准入前构造服务，各构造器可能创建表、迁移列或写 `user_version`。现在 app 装配时延期全部 schema 初始化，包括后装配的 `ChapterCommitIndex`；只有取得维护写准入后才执行初始化和启动恢复。中断维护下仅使用 `mode=ro`、`query_only` 连接，不设置 WAL。不存在或不兼容的旧表返回明确的 503 初始化待完成信息，维护状态及页面仍可访问。初始化失败保留未完成队列，已经成功的组件不重复执行。

另一个缺口是 SQLite `iterdump()` 不能发现隐藏 rowid 或 `application_id` 的变化，因此旧实现不能证明调用方事务没有未提交状态。`owned_database_snapshot` 现在自行创建全新 `BEGIN IMMEDIATE` 写锁连接和只读视图；不接受调用方事务，预检只取得受 authorizer 限制的只读连接。写锁保持到整个上下文结束。`capture_database` 只接受该上下文的活动句柄，备份复制和完成检查仍验证维护许可、物理身份、完整性及外键；逻辑摘要补充行号与元数据。写入、修改 query_only、ROLLBACK 和 ATTACH 都被拒绝。

## 预检范围

`inspect_backup_scope` 读取同一登记数据库事务，核对工作区内的目标作品、已登记目标任务的服务端 runtime 根、数据库内草稿/候选/润色/章纲及常见任务文件引用。候选 `source_artifact_ref` 实际相对于 `.novelagent/runtime`，已经按真实格式处理。其他作品文件不加入范围，整库快照仍保留其记录，恢复必须默认禁用这些作品。

预检检查已审核格式的完整历史、未恢复 journal/pending/staging、候选/事实提取的来源和终态、物理模型回执及响应文件、预算占用和主动时间区间。缺文件、秘密文件被排除后仍被引用、未知外部根、未决任务/调用、损坏证据会产生 blocker，不进行恢复或对账。`scope_checks_passed` 只是本次预检结果，`archive_certified` 永远为 false。

旧格式存在 transactions 历史时，完整历史认证仍待实现，因此明确阻断认证；不把旧单事务实验当成多章恢复证明。尚需扩展任务深层引用和必要外部根的完整来源映射，结合所有写锁重新核对最终范围。当前预检没有独立产品 HTTP/页面入口，也尚未完成归档。

## 产品维护入口

新增 `/api/maintenance/{begin,resume,finish}`。专门控制路由仅允许这三种转换，不把自身算进正在排空的普通写操作；保留 app 外层 Host/Origin/会话令牌校验。原 operation_id 必须匹配，中断维护须先显式接管，存在实际写入或 capture 时不能结束。结束维护后的初始化仍在可排空的实际任务许可中执行；HTTP 断开不会释放正在运行的初始化线程。

主工作台增加维护状态、进入维护、继续原维护、结束维护和手动刷新。结束前明确提示将恢复编辑与任务调度。控件本身不创建备份。状态在进入页面、重新获得焦点和表单错误后刷新；持续排空时可手动刷新，不推断超时即结束。独立发布页仍由后端准入保护，其完整维护状态展示尚未补入。
