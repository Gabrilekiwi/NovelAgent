## 结果与支持范围

恢复出来、已经取得机器资格 V3 的 Strict 旧书，现在可以通过内部原格式升级事务将格式 1.0/2.0 升为 3.0，并延续同一原恢复资格。原 `write-qualification.json`、作品登记凭证、原机器启用意图及完成回执不被重写；完成后只推进机器代际和已验证的新身份摘要，保留原资格 SHA 与登记 ID。

实际验证了两条后续恢复路径：升级前在此恢复来源保存的旧格式归档，可以在升级后交接并恢复启用旧格式；升级后新归档也可以经历真实回退，再以同一归档恢复启用新格式。目标均经两次实际工作台启动和作者草稿读回检查，不运行 worker、自动导入或模型调用。

这些结论属于内部工程验证。公共作者基线确认/升级入口仍关闭，归档仍 `diagnostic` / `recoverable=false`，完整可恢复认证尚未签发。原始机器登记 V2 的升级前备份到升级后当前身份之间的恢复证明关系，仍是下一项工程；不能把本批“恢复来源 V3 的旧归档已通过”扩大为所有旧备份均已支持。

## 实现与资格边界

- `registered_identity_upgrade.py` 增加明确的 `registered_restored_identity_upgrade_v1` 意图，冻结实际原恢复来源证明，并维持原来的应用前 `identity_upgrading` 栅栏。未改变原始登记 V2 的旧意图协议。
- `restored_identity_upgrade.py` 将实际原升级意图、完成凭据、最终事务 manifest 和发布回执绑定成独立的恢复资格升级续接。只有这些原文件和原恢复本地/机器凭据均核验通过，才发布资格续接并使新机器记录活动。
- `restore_reinstatement.py` 支持按实际顺序核验升级续接和既有回退续接。离线关系核验不打开祖先目录；活动资格检查还核对实际原事务和原机器文件，不凭代际递增、单个新摘要或缺失凭据重建来授权。
- `restore_qualified_archive_ancestry.py` 允许完整有序续接链证明的身份摘要变化。物理根、数据库绑定、作品凭证、原资格与原证明前缀仍须一致；没有升级续接的身份变化不能放行。

明确续接仍只处理原事务目录/原 run ID：提交标记前回退原应用，标记后完成原发布。原恢复范围、历史保留表、本地原资格/计划/复制/根/SQL/执行隔离文件及原机器启用依赖均重新检查。普通写入及通用自动恢复不能绕过在途栅栏。
