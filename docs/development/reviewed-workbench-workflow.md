# T3.2 新版作品主工作台接入

2026-09-10；仍是阶段中的组件检查点，完整两模式与后续阶段未完成。

`ReviewedWorkflow` 在原工作台路由内明确区分普通作品与已升级 identity 3.0 的作品。原服务、普通 ProjectRegistry、CLI 和旧 worker 的格式限制保留；没有提高全局 writer contract。

新版章节卡、Candidate、事实提取和作者审核使用明确的 Reviewed builder/registry；事实提取仍走原 recoverable executor 和原 Provider 证据协议，只替换服务器选择的可信上下文构建器。生成、恢复候选、创建/编辑草稿、提取、取消、处理 Provider 不确定结果、审核编辑与确认都经过机器作品所有权。读旧证据不主动取得写许可。

锁顺序为：机器作品锁 → Provider 边界 → 同一数据库内核验登记/所有权并恢复原正式事务。执行 Candidate/提取之前释放内层 Provider/DB 锁，保留机器作品锁，由执行器取得自己的 Provider 锁，避免嵌套死锁。存在 Provider 不确定调用时，不恢复正式文件，只核验正式事务已终结，以便明确放弃不确定结果的动作仍可执行；新模型调用仍由原执行器的全作品不确定门阻断。

`ProjectDisplayRegistry` 仅交给 GET 展示分支，不交给写服务。新版作品的书架、概览、健康、章节与导出使用独立视图；状态和正文由正式历史/receipt核验。部分 apply 的作品显示待恢复、不猜测游标，不会先由严格 reader 使整本作品无法打开。新浏览器不需要 localStorage/key，直接通过章节 API 取得正式已发布状态。人工来源变更时保留已核验历史，但暂停新写作。

已确认审核返回服务器构造的 `publication_url`，主页面审核卡下方自然进入现有发布页。发布页返回本章后显示正式正文，已提交旧章节不再请求新章节卡或错误地重启候选。新版尚未完成的自动生产/旧任务历史/章纲规划能力以 capabilities 明确为 false，对应入口暂不显示；这是未完成范围，不能据此宣称两模式目标已完成。旧书入口继续原行为。已升级作品不再展示旧 Strict 激活表单。

## 验证

自动测试使用实际升级+登记、确定性正文与带真实持久调用记录的假事实 Provider，网络调用为0。覆盖主API生成候选→提取→编辑审核→确认→标准预览→发布；未登记和持久恢复阻断下不得创建executor/修改草稿；不确定调用阻断新调用但可明确放弃后继续；部分apply时主页面可读取并恢复；无浏览器key的正式章节读取与导出。两组旧应用、候选、提取、静态契约回归保留。按用例名取最新结果的57个不同用例均通过，XML/hash见stage-c-progress。

实际浏览器见 `reviewed-workbench-browser-verification.md`。浏览器发现并修复：发布链接不能放在审核锁定后被CSS隐藏的编辑footer内。旧静态测试还发现导航统一重写语句被改写，已保留默认重写、再施加新版capability分支；旧测试23项重新通过。所有早期失败XML均保留。
