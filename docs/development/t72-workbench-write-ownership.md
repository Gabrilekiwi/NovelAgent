# T7.2 基础：工作台章纲、规划和润色写入资格

日期：2026-09-14。范围为受支持工作台入口的机器资格和实际数据库登记核对；不等于完整恢复交接完成。完整 A–F 目标仍进行中，恢复副本仍只读。

## 实现与边界

`workbench/book_writes.py` 在普通可写数据库连接之前，通过 `mode=ro` 读取真实登记，按书根和 book_id 取得机器锁，然后复读登记。后续检查实际数据库物理身份、数据库路径、project_id、书根与机器账本绑定；写事务开始和提交前再次核对。连接不能来自另一数据库，其他线程或已退出的 scope 不能借用资格。

读取活动 SQLite 必须包含已提交 WAL；没有使用会忽略 WAL 的 `immutable=1`。SQLite 可以创建、维护或清理 WAL/SHM 辅助文件，因此拒绝写入的承诺是业务数据及作品文件不变，不是操作系统层面的零文件活动。测试核对完整 SQLite 逻辑内容、所有普通文件，并禁止被拒绝请求调用普通 `_open` 可写连接。另有保持 WAL 活跃、把批次归属更新留在 WAL 中的反例。

- `OutlineBatchService` 的创建、更新、批准和采纳已有细纲入口，在数据库事务、目录创建及发布前持有资格；原 revision/hash/source CAS 和正式章纲事务保留。
- `OutlinePlanner.propose` 从登记调用、Provider、契约修复到保存结果和完成/失败登记持续持锁。取得 operation 后绑定原始记录归属；内部保存使用同一 scope，防止 Provider 返回时把记录重新路由到另一部活动作品。
- `AmendmentService.submit` 从保存待审核版本到 Provider、manifest、活动版本指针和状态提交持续持锁。活动指针写入位于已经重新核对的数据库事务内。正式正文保持不变。
- 中断恢复逐条检查记录所属作品。无资格或被占用的作品保留原记录，其他合格作品可以标记 `needs_recovery`；不重放 Provider。只有事务及外层资格检查成功后才计入恢复数量，回滚不计成功。启动警告说明被保留的记录数量。
- API 使用 HTTP 409 和 `book_ownership_invalid`，界面提示“这本作品当前没有可用的写入资格。请在活动副本中操作，或先完成恢复交接。”

普通尚未登记的旧书仍保持兼容。这里没有实现正常用户首次登记、缺失账本证明、机器资格代际交接或恢复启用。
