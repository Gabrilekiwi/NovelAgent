# T5.1 模型调用用量与费用验收

2026-09-10，工作树实现。范围是调用证据与展示；金额预算限制属于 T5.2，连续自动预算属于 T5.3。

## 实现

- `core/model_call_usage.py` 从已经核验哈希与关联关系的 Intent/Receipt 投影物理调用。去重身份为执行/操作身份加 attempt_id；重放回执不会增加次数，不同执行中的同名 attempt 分开计算。
- 展示阶段、请求模型、返回模型、服务商、端点类型、原开始/回执时间、结果、token 来源、预算预留和费用依据。成功、部分响应失败、预算拒绝、未发送、服务商拒绝及无回执均保留。
- OpenAI/Claude 适配器仅对实际返回的非空 SDK usage 标注 `novelagent_usage_source=provider_reported`。原始兼容端点返回值不能自行指定内部费用归因。旧回执保持原字节与哈希；旧正数量标为旧回执记录，无来源零值、缺项和冲突字段显示未知。程序估算保持独立来源。
- 预算预留不当作实际 token，缓存/推理明细不再叠加到总 token。失败路径中的本地合成零值不冒充服务商用量。
- 费用分为 actual/estimated/unknown，按币种分别给实际与估算小计。存在未知费用时明确提示小计并非完整费用。使用 Decimal，汇总不经过二进制浮点货币计算。
- `workbench/model_usage.py` 只读核验章节/自动执行及旧工作台章纲规划、润色操作三种实际目录。发现孤立回执、哈希损坏、文件名不符或超出报告上限时，拒绝输出部分合计。新接口为 `GET /api/projects/{project_id}/model-calls`；适用于已登记的旧版和新版项目，不赋予写入/升级许可。
- 项目概览、章节、历史页面下方可展开“本作品的模型调用、用量与费用”。默认不请求；展开或显式刷新只执行 GET。换项目后旧请求不能覆盖新页面；核验失败会清空旧合计。
- 修复实际独立导入 `core.model_calls` 时暴露的 `api.__init__` 循环导入：保留公开包装器，延迟导入需要持久运行时的 Provider 适配器。既有包装器身份回归通过。

## 费用来源契约与边界

费用依据可由受信适配器放入现有可扩展 usage 字段中的 `novelagent_cost_evidence`，它受原 Receipt 哈希约束，不建立第二本费用账，不修改旧回执。契约版本为 `model_cost_evidence_v1`，要求 classification、amount、currency、source、source_id。

- actual 要求明确服务商费用凭据来源；仅有 cost=0 或 estimated_cost=0 不够。
- estimated 要求价格快照标识与实际返回模型/端点对应、完整输入和输出数量/单价计算、金额相等。当前只接受未使用缓存的输入/输出计价；缓存及其他未完整建模的计费语义显示未知，不给不完整估算。
- 当前标准 SDK 适配器没有账单接口或已配置价格来源，因此普通真实调用的费用会显示未知。这是来源不足的实际状态。没有采用未经核验的现时价格，也没有把夹具费率当作模型真实报价。价格配置与执行前预算仍在 T5.2 实现。
- 返回模型为旧回执原样保存的元数据；旧适配器可能以请求模型作为缺失实际模型的回填，不能据此证明服务商实际执行了该模型。
- 报告最多核验 10,000 次尝试，超出时明确报错而不截取后假称总额。旧无单次凭据的历史摘要不会被伪造成新物理调用，空报告也不证明旧运行免费。
