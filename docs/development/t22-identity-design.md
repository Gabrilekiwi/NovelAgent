# T2.2 实现前调查

> 后续结论：T2.2已完成后端接入、正式提交及下一章冷读验收。本文保留调查历史；最新证据见`t22-support-workflow.md`与`t22-support-browser-verification.md`。

2026-09-10；T3.2最终全量验收尚未结束，T2.2未标记完成。身份解析独立组件已有验证；审核、基线与正式提交接入待实现。

现有 `chapter_fact_context.py` 已有带种类、稳定ID、名字/别名的实体目录，覆盖legacy、Reviewed与EA，并为事实提取提供消歧视图。目录是从权威资料派生的，不能把这个提示词视图直接作为可写基线。`chapter_fact_prepare.py` 已拒绝未知引用、未知位置、缺库存和计数基线，并禁止用普通状态字段修改身份。`authoritative.py` 已约束人物别名冲突和规范名称漂移。T2.2应补声明与明确处理，不再建另一套提示词目录。

实际缺口：

- 同章新人物、地点、物品还没有经过作者决定的稳定身份声明，无法先声明再引用。
- 提案携带一个存在的ID不证明正文中的昵称已消歧。离线样例 `ambiguous_nickname` 仍是策略缺口；不得把模型选中的周岚ID当成作者消歧。
- 缺失台账已被阻断，但没有接受显式基线的操作。不能将没有库存台账解释为数量0。
- 七类状态中的 `locations` 是实体当前位置，`inventory` 是持有人/物品数量台账；它们都不是独立地点或物品目录。不能靠伪造位置、持有人或零库存声明一个新实体。

优先验证的路径：将身份声明、已有身份选择和基线补充作为有版本的作者审核决定，保留原始模型建议；由服务器生成并保留新ID，以种类和明确别名进行解析。只为缺失值补基线，已有值冲突走明确错误，禁止覆盖已绑定的来源。相关决定必须纳入事实修订/确认哈希、最终正文与上下文CAS，并进入T3.2正式请求与冷读重放。

持久化需要先验证：利用现有正式状态/事件的结构化决定证据派生人物、地点和物品目录，避免把物品身份塞进假的库存台账。若既有记录形状无法完整承载，则显式版本化格式，不能添加会被旧reader静默丢弃的字段。普通EA路径继续原有约束。

验收必须包含同章声明与引用、已有别名复用、未知/重名拒绝或明确选择、缺基线拒绝与作者补齐、已存在基线不可覆盖、被拒声明不得供其他事实使用、改稿后决定失效，以及真实共享提交后新进程下一章读回。T2.3再把这些决定做成不需编辑JSON的正文对照界面；T2.2不能只通过纯函数就声称下章已读回。

## 已验证的独立身份组件

`core/engine/chapter_fact_identity.py` 接受现有 `chapter_fact_context` 的完整实体目录形状，不创建另一套持久目录。ID查找与名字/别名查找明确区分，使用NFKC及大小写归一化后的精确匹配；不会从姓氏推断昵称，也不会去掉标点做模糊合并。重名返回完整候选；选择必须属于实际候选集合。

作者可通过独立的declare/reuse决定声明新实体或将本章称呼明确绑定到已有ID。未知称呼的作者绑定只作用于当前审核，不静默新增全局别名。新ID由作品ID、持久审核scope、local_key和种类派生，不因排序或修改显示名称重新生成；同名/别名冲突需要复用或消歧。结果保留输入目录哈希、完整决定、局部引用、派生目录及计划哈希，始终 `publication_authorized=false`，不建立数量或位置基线。

`tests/test_chapter_fact_identity.py` 20项通过，含实际Reviewed Candidate的事实目录接入；XML为`.tmp/stage-c-t22-identity-verified.xml`。第一次集成测试错误地把夹具中的builder类当成实例调用，已改为直接核验隔离书的实际章游标；失败XML`.tmp/stage-c-t22-identity-final.xml`保留。早期17项纯函数结果见`.tmp/stage-c-t22-identity-initial.xml`。

## 接入时必须保持的实际边界

- 当前`chapter_fact_review_item.schema.json`与`_normalize_review`严格限定四个review字段；`_author_update_transition`还禁止增删事实卡。身份/基线决定需要明确版本和审核存储接入，不可只在调用prepare时临时塞一个未确认的字典。原模型提案及来源必须保留。
- `prepare_confirmed_fact_changes`目前只接受facts、正文和base_state；正式准备、质量核验、`prepare_chapter_document`及`verify_transition`都实际重放它。若稳定ID需要book_id/review_scope，这些调用必须一致绑定，不能只改工作台端。
- `reviewed_chapter_quality.py`在重算事实准备后，还独立把state_delta应用于原始权威状态。显式补齐基线必须有原状态→已批准补充→章节变化的完整可重算证明，不能直接把未知基线换成一个更容易通过的状态。
- 地点/物品声明的持久证据必须在正式历史及下一章上下文中可重建。可调查将有类型的声明证据保存在现有已核验事件记录中；具体编码尚未接入，也未通过冷读验证。不得用不存在的库存、持有人或位置记录替代身份目录。
