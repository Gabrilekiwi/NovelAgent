## 材料与来源

12个版本化用例存于`tests/fixtures/chapter_fact_offline_v1`。清单绑定基线与每个用例的字节哈希；用例记录原材料路径、原材料哈希、预期处置及中文理由。组成包括：

- 七类混合事实；明确零库存；缺失库存基线；同一计数的歧义顺序。
- 漏库存事实、含明显变化却返回空提案、同事件重复库存变化、依赖被拒事件。
- 同昵称多人物、正文中无移动却切换地点。
- 复用已有的重复救援、合理重复和正常章节样本。

另保存3份只读真实材料的哈希与隔离副本：目标书第26章正文、一份已保存的场景生成响应、一份已保存的空问题列表响应。清单只保存来源信息，原始内容位于`.tmp/stage-b/offline-source-snapshots`，没有加入Git。三份材料不假定属于同一次调用或同一章节，不拼成虚假的输入输出对。

观察重点：第26章的楼顶在场者与楼下远程协作需要区分；旧生成响应的subjects/objects/location不等于新事件角色契约；空问题列表不构成人工认可或无遗漏证明。真实材料仅作为后续策略审查的来源，尚未纳入自动评分。

所有新增注释均注明由agent整理，人工复核状态为pending。合成用例的预期来自其明确构造条件，既有回归用例沿用原预期；没有把agent判断改写成人工九维分数。

## 执行

在仓库根目录运行：

```powershell
.venv/Scripts/python.exe -B scripts/check_fact_offline_suite.py --output .tmp/stage-b/offline-report.json
```

需要核对本机真实来源及隔离副本时加`--verify-local-sources`。默认只使用随代码保存的合成/回归用例，CI不要求正式作品存在。

需要把语义策略完整覆盖作为门槛时加`--require-policy-complete`；当前该模式应返回退出码1并保留报告。日常离线运行的退出码0只表示固定结构回归未退化，不能当作全部质量检查通过。
