# 第63章到第64章的记忆源头修复

本轮修复旧格式记忆写回、读取及质量检查中已复现的缺陷，并按作者先前指令校正原书第63章末当前场景。没有新付费生成，没有第64章正式提交，没有宣称完整记忆系统或上线验收完成。

## 已查实的原因

第63章持久执行记录 `books/尸潮之下_我能提取进化词条_重写V2/.novelagent/runtime/runs/chapter_63_20261111T060325488542Z.json` 的 `character_changes` 为空。旧写回合并保留历史人物值，却只记录整个文档的最新章节，所以早期“公开账／两处最低数”被带进第63章标记的投影。不是本轮证据能证明的“第63章正文后来被改过”。

手工人物表采用哈希标识，自动记录使用姓名，读取时出现两份陆沉；初始商超位置按手工优先规则保留。场景连接词“最后”仍留在旧记忆中。`pending_threads` 没有进入仅投影 `open_threads` 的写作输入，也未被质量检查读取；开篇检查仅匹配人名即可通过。

## 机制修改

- 每项新写回记录绑定原始来源章节、执行标识与正文摘要；继承项保留自己的来源，不能冒充最新章节。旧记录不补造来源。
- 读取时核验来源正文；改稿、来源缺失、观察引文不在来源中、身份冲突和无效场景地点会要求先核对记忆。旧格式生成入口在模型调用前执行检查；已审核事实及事件权威路径维持既有独立入口。
- 来源可核验且手工区域未变时，新的自动人物状态合并到同名人物，替代初始动态值；手工区域后来改变且出现冲突时拒绝猜选。位置与别名字段保留可追溯来源。
- 空的人物位置表不再抹去整个空间状态。没有提取到线索不再删除旧写回中的未完线索。`pending_threads` 保留独立字段进入模型和检查，不冒称它与另一份列表原本相同。
- 无效地点、与最终正文不符的人物观察在旧格式写回前被拒绝；已有正文版本绑定时，修改章节不能通过同一写回入口静默跳过旧记忆。
- 质量检查不再仅凭人物姓名判定衔接通过；无效地点提示为记忆问题。仍是启发式检查，不是文学质量证明。
