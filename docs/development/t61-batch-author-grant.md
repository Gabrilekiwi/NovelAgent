# T6.1：有限批次的原作者授权

2026-11-05。本组件实现服务器生成并持久化原作者授权的内部服务。**自动批次驱动、逐步执行许可、policy 事实审核/正式接受、修复/重提取/重检、连续正式提交仍未接通，整个 T6.1–T6.3 与 D/E/F 未完成。** 没有真实 Provider 调用、真实作品写入或新增正式接受。

## 授权所依据的实际输入

workbench/reviewed_batches.py 使用现有 ChapterPublicationService._owned_project，锁顺序为机器作品所有权、Provider 排他、SQLite 写事务；核对原注册和所有权，未恢复事务及不确定调用均阻止新授权。没有绕过 Reviewed v3 格式与恢复资格。

预览接收章数终点、单章/批次预算配置和幂等键。实际 book/project/root、当前待写章、历史及基线、所有选中章纲字节和解析蓝图、人工来源、当前配置中的精确模型/端点指纹、重试及输出控制、标准质量策略、版本化处置策略、软件磁盘源指纹均由服务器生成。客户端不能提供可信状态、蓝图、质量结论或授权记录；批准时必须与原预览 SHA 一致。

批次从当前正式待写章开始，最多 64 个连续章。每章章纲必须唯一并具备核心事件、必要节拍、结尾压力。每章及批次须有同币种显式定价；定价须匹配当前配置的精确模型与有效端点。没有自动选模型、替换为便宜模型、保存密钥或原始端点 URL。

原授权记录区分 grant_source=author 和 automatic_review_source=policy。前者是作者对有限批次的明确确认；后者只描述后续审核必须记录的来源，**当前没有调用人工事实确认接口并伪造 author_confirmed=true 作为自动审核**。

## 原授权的持久化与重启

明确确认后，服务器先在原机器所有权目录写不可变 bg-batch_*.json，再初始化原批次预算，写作品中的 reviewed/batches/batch_*.json，最后写原机器完成凭据 bgr-batch_*.json。所有原授权绑定 ownership record SHA、project、book、物理原根、原预算、原政策和原章纲/来源。同一幂等键不能换授权内容。

读取要求机器原授权、作品副本、完成凭据和预算均吻合。只有作品副本、客户端声明或重算哈希不足以授权；机器证据缺失时不能从作品拷贝重建。未完成的原请求仅通过明确确认后续办，不在服务构造、读取或工作台启动时自动完成，更不派发调用。

状态返回 authorized_paused、explicit_resume_required=true、execution_permit=false、provider_calls_started=false。require_current_start 只核对原初始输入/模型/策略/软件仍匹配，不是执行 token，不派发 Provider。后续步进驱动还必须证明前一章正式事务及 readback、当前原始读集及有效预算，并分别处理暂停、停止和显式继续。

审批预览使用现有所有权排他边界，首次访问会惰性创建 1 字节 Provider 互斥锁文件。第一轮断言要求整个目录字节不变因此失败，记录保留在 `.tmp/t61-grant-first.log/.xml`。断言现在只容许这个确切新锁出现，同时验证所有原文件不变、总字节仅增加 1，并要求第二次预览整个目录不变；预览不建立预算/授权、不改草稿或正式内容。
