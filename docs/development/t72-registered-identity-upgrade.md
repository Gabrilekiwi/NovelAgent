# 已登记旧书格式升级的机器身份衔接

日期：2026-10-19。完整 A–F active，A/B/C 保持工作树内部验收，D 继续，E/F 未验收。本组件不开放公共升级入口，也不签发可恢复认证。

## 已复现的问题与实现

原句柄 73588 observed exit 1：通过实际公共旧书登记 API 获取机器所有权后，内部格式升级成功提交、冷读也通过，但机器记录仍指向旧身份摘要，随后 `BookOwnership.require` 拒绝写入。这是实际登记与实际升级的衔接缺口，未手工合成机器登记；Strict 校准与七类作者基线仍是明确的合成测试数据。

新增 `workbench/registered_identity_upgrade.py`，由 v2 事务的机器写入边界接入。对原始登记的机器所有权 V2，完整原升级 manifest、原登记和拟完成记录共同绑定持久意图；在应用身份/状态前写入 `identity_upgrading` 栅栏。普通写入及通用自动恢复不能使用在途资格。原事务提交凭据、不可变前后身份/基线归档核验完成后，才发布完成凭据并推进当前身份摘要与代际；原登记 ID 和作品凭证保持不变。

`resume_registered_identity_upgrade` 只接受原事务目录和原 run ID，不扫描目录、不重新登记。提交标记前按原事务前像回退，标记后完成原事务发布；数据已经完成但机器资格仍在途时，允许明确继续原完成步骤。已启用升级资格则必须保有实际原意图和原完成凭据，丢失时拒绝正常写入和续接，不自动重建。正常资格核验还读取实际原事务与发布证据，不能只凭新摘要或更大的代际放行；后续同绑定回退沿用已实现的实际回退证明链。

此处“格式 3.0”与“机器所有权 V3”不是同一概念。本文所记录的初始组件支持原始机器登记 V2 的格式 1.0/2.0 → 3.0 升级。后续恢复来源 V3 的资格升级及其旧归档复用，已在 `t72-restored-identity-upgrade.md` 另行实现和内部验证；本文历史测试仍保留各自指纹，不重计为该后续组件证据。原始登记 V2 的升级前归档到升级后当前身份的恢复/回退证明关系仍待实现，公共升级许可仍关闭。

## Windows 长路径仍待解决

整链测试最初使用很长的 pytest 机器目录，已有 `handoff-<完整 SHA>-intent.json` 超出当前环境的路径支持。仅给原子移动的 Win32 API 添加扩展路径前缀，虽然能创建长名称文件，后续 Python `lstat`/读取仍失败；独立探针也验证了这一点。该不完整的全局改动已撤回，原 `_windows_move_file` 保持原行为；未修改系统注册表或用户浏览器/系统配置。

当前恢复整链使用独立的 `.tmp/常规升级 恢复-<随机值>` 机器目录，覆盖中文和空格以及与默认配置相当的路径长度。它不证明任意长路径可用。长路径支持仍作为 F 阶段的发布阻断保留，不通过缩短夹具来宣称问题解决。背景可参见 [Microsoft 的路径长度说明](https://learn.microsoft.com/en-us/windows/win32/fileio/maximum-file-path-limitation)。

历史失败证据还包括 59589（早期新文件名过长）、27439（测试遗漏私有 scratch 夹具）、96092（原 handoff 长路径）、50319（原子移动的扩展路径试验后，10 通过/1 个读取失败）。临时 native-path 探针测试已移除，日志仍保留，不作为当前成功测试报告。
