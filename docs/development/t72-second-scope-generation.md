## 原问题与限定变更

上轮实际第二个恢复副本在 `_insert_scope` 的“只能首次登记”保护下拒绝绑定。保留该默认保护；只有完整来源恢复证据与原 SQL scope 一致时，内部恢复服务才能产生新代际。

- 首次恢复继续使用 `restored_workbench_scope_v1`，第一代隐含为 1。再次恢复使用 v2，新增 `scope_generation`、完整 `predecessor_scope` 和 `source_provenance_sha256`；前一代所有字段作为完整对象保留，不写旧机器活动记录，也不执行旧路径。
- 新范围同时绑定新数据库/书籍的实际物理身份、原计划、归档和来源证明。原 SQL 行必须与归档中上一代范围完全一致，目标路径索引和新 scope 在同一 SQLite 事务更新。普通登记不能覆盖既有范围。
- 范围加载核验本地原计划、数据库意图与祖先链，重新计算摘要和代际；双份本地 scope 即使一起重算摘要，仍不能降级、跳代或改变来源绑定。
- 活动机器资格属于另一个物理根/数据库时，新副本保持只读。活动记录指向本副本而本地写入资格丢失时继续拒绝启动，不能借此退为普通工作台。
- 新副本数据库保留旧任务完整行、事件、旧任务历史表、作者草稿、预算引用和其他作品的 SQL 数据，范围仍只允许目标作品。这个步骤不撤销源资格，也不启用新副本。

初步演练 `.tmp/t72-second-scope-probe.log` / `.json` 为实际新副本：第二代 scope、原范围一致、重复准备相同、只读工作台目标列表、零自动执行、书籍字节不变。该演练在后续小幅加固前完成；最终结果以正式测试为准。
