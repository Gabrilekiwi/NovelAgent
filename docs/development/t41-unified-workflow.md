# T4.1 统一章节流程验收

日期：2026-09-10。工作树实现；完整 A–F 目标仍在进行。本项不替代 T4.2 两章及四断点浏览器重启验收，也不代表真实模型质量已验证。

## 已实现的行为

- 章节顶部统一连接章意图、生成与编辑、事实审阅、预览发布和下一章。未发布章默认打开章节卡；步骤按钮切换到对应区域并定位焦点。正式章显示正式稿并开放下一章入口。
- 页面区分可编辑草稿、生成中、检查中、待审阅、事实需重查、待发布和正式稿。已存在的草稿及审核从服务器持久记录读取。
- Candidate 与事实执行器在原有 Provider 写入边界内持有单次执行观察锁。操作系统释放锁即不再表示运行，遗留文件不能冒充存活；它不提供新的执行/提交许可。
- 只读页面以 GET 查询当前显示的精确执行。终态后停止轮询，不从定时器启动或恢复模型调用。响应须匹配路由代次、候选、草稿修订/SHA、提取和操作代次；写操作或未保存事实不被旧读响应覆盖。
- 终态恰好在第一次读取与存活探测之间落盘时，再次读取终态证据，避免把已经完成的执行显示为需要恢复或调用不确定。
- 修复异步确认弹窗后 `event.currentTarget` 被浏览器清空的问题：提前保存按钮引用，确认后正确禁用按钮、显示生成/检查进度。
- 新增显式 `POST /api/candidate-drafts/{draft_id}/fact-extractions/{extraction_id}/review`，请求带 `expected_record_hash` 和 `author_confirmed=true`。只核验已完成的结果并建立/找回审核，不构造执行器、不调用 Provider。GET 不自动建审核；再次导入保留原审核和作者修改。
