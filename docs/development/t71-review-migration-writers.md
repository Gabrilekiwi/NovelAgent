# T7.1 审阅输出与旧运行目录迁移的写入协调

日期：2026-09-11。T7.1 累计 164 项新增不同用例，完整 A–F 目标仍在进行。

## 已完成内容

- 审阅看板（库函数、main CLI、独立脚本、自定义路径）与审阅索引更新现在先取得共享状态锁，再创建目录和发布文件。索引的读取、合并与更新也在同一锁内。发布复用原有原子替换函数，HTML 内容、链接与 CLI 参数保持原语义。
- 输出路径逐级检查实际父目录中的作品身份标记，锁住输出文件及所有包含它的已标识作品；不信任索引正文声明的路径。即使默认 reviews 或自定义输出的父目录尚不存在，拒写也不会在作品内留下新目录。临时锁在系统共享状态锁目录。
- 新增 `persistence_state_lock`，与既有 run lock 共用状态锁路径计算。仅当前线程和 ContextVar 中仍有效的持有者可借用自己的锁，供生成期间嵌套更新索引使用；原 `persistence_run_lock` 仍非重入。线程复制上下文不能借用，退出后的旧上下文必须重新取得锁。
- 旧运行目录迁移在预检、身份初始化、暂存、发布的整个过程持有作品状态锁。备份把同一个作品锁提前到创建 Provider/runtime 锁目录之前，防止侵入“runtime 原先不存在”的迁移窗口；后续机器、Provider、数据库、EA、fence、局部持久化锁仍保留。
- 真实迁移测试发现原暂存目录重复完整迁移编号，造成 Windows 中最终路径合法而暂存路径超长。暂存目录改为短随机名称，正式迁移编号和清单内容不变。此修复没有声称支持任意长度路径，也没有改变迁移源目录的复制语义。
