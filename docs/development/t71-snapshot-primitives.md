## 实现

维护协调器新增capture许可：仅在当前原维护操作排空后取得，期间显示capturing。复制期间不能finish、resume或开始第二份capture；异常退出只结束本次复制许可，维护请求仍保留，不自动恢复写入。

`workbench/backup_database.py` 接收已锁定的工作台事务和capture许可，以不修改任何行的UPDATE保证数据库写锁，通过另一条只读连接调用SQLite backup。比较锁定事务、已提交只读视图及副本的完整逻辑摘要和user_version，检查完整性与外键，保留所有表/索引/登记/草稿/任务；未提交修改不能被静默漏掉。目标必须是新的独立文件，最终关闭为不依赖WAL的单文件，给出内容哈希和大小。复制期间重复检查许可及数据库文件物理身份；失败保留未认证暂存物，不返回成功凭据。

`workbench/backup_files.py` 对指定必要根流式生成有上限的清单，包括正文、隐藏runtime文件、空目录、文件哈希/大小和源物理身份。默认最多10万路径、20GiB；超过则明确失败，不给截断清单。拒绝链接、reparse、硬链接和非普通文件；使用既有SafePathResolver核对父目录身份。排除.env/.env.*、常见凭据文件/目录及私钥扩展名，清单记录排除原因，不读取其内容。此处是已知凭据路径排除规则，不声称发现任意正文内人为放入的秘密。

复制要求新且不重叠的暂存目录，预览清单必须仍与来源完全一致；逐文件写入后flush/fsync，再核对来源和目标哈希及范围。来源文件增长、内容/范围变化、暂存根或父目录替换不能产生成功复制凭据。副本保留不同物理目录身份，供T7.2按恢复来源证明建立新绑定，不改旧历史。

- 正向SQLite测试实际创建两本登记作品、目标作者草稿及任务，用中文/空格路径保存副本。backup进度回调启动独立本地Python进程竞争BEGIN IMMEDIATE，退出码17并返回database locked；副本全部记录和草稿一致，integrity_check通过、无-WAL文件。覆盖未提交修改、已有目标、复制中断和维护记录损坏。
- 文件首次专项使用未注册PathRef根名被既有验证器拒绝；改为已支持的`external:backup_source`临时只读绑定，不放宽核心验证器。随后增加暂存目录替换、目标父目录guard和文件增长检查。
