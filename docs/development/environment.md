## 安装与检查

Windows使用CPython 3.12，PowerShell中在仓库根目录运行：

```powershell
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
py -3.12 scripts/setup_environment.py
.venv/Scripts/python.exe -B scripts/check_environment.py --dev
.venv/Scripts/python.exe -m pip check
.venv/Scripts/python.exe -B -m pytest -q
.venv/Scripts/python.exe -B scripts/smoke_v1.py --skip-tests
```

没有`py`启动器时，用已安装的Python 3.12绝对路径运行setup脚本。Linux使用`python3.12 scripts/setup_environment.py`，之后将解释器替换为`.venv/bin/python`。脚本只创建或更新仓库`.venv`，不安装到全局环境、不启动服务、不调用Provider。已有虚拟环境若版本错误，脚本停止并报告原因；先确认目录用途，再另存旧环境并重建，不能直接覆盖未知数据。

Windows测试前在同一PowerShell窗口设置上述UTF-8环境，再启动Python，使父进程与它创建的子进程使用一致的文本编码。不要只在Python已启动后设置`PYTHONUTF8`：它不能改变该解释器已经确定的默认解码方式。若使用`python -X utf8`，仍需给子进程继承相同环境。双击启动器及CI已设置UTF-8；这里补齐手动测试步骤。

只安装运行依赖可加`--runtime-only`。Windows双击启动器会核对Python、虚拟环境和运行依赖版本；不满足时显示修复命令。首次安装需要包源网络，常规启动只做本地版本检查。

当前固定30个运行依赖及5个开发附加依赖，来自已有通过测试环境的项目依赖闭包，不包含全局环境中的无关包。`colorama`仅Windows安装。锁定版本可以减少依赖升级导致的环境漂移；这是版本锁，尚不是带全部分发包哈希的离线安装包。[pip可重复安装文档](https://pip.pypa.io/en/stable/topics/repeatable-installs/)

`requirements.txt`和`requirements-dev.txt`保留顶层允许范围；`requirements.lock`和`requirements-dev.lock`为安装入口。更新依赖时在隔离Python 3.12环境中按允许范围解析，检查直接及传递依赖，更新两个锁及原因，执行`pip check`、相关测试和smoke，再通过CI验证。不要将整个开发者全局环境的`pip freeze`原样覆盖项目锁。

CI配置已接入Ubuntu和Windows，均使用相同锁与项目环境，并执行环境检查、全套测试和离线smoke；Windows输出使用UTF-8。提交 `cf5fa25` 已通过 Windows 和 Ubuntu 的远端检查。Windows发布及平台场景完整验收属于T7.3，不能用本机环境检查代替尚未运行的远端CI。

## Windows候选版安装与日常启动

当前开发版本尚未完成T7.3发布验收。以下是安装和维护操作说明，不表示已经存在通过验收的稳定安装包。

将项目放入固定目录；路径可以包含中文和空格。先安装CPython 3.12，再在该目录按上述命令创建项目环境。只运行工作台时可使用：

```powershell
py -3.12 scripts/setup_environment.py --runtime-only
.venv/Scripts/python.exe -B scripts/check_environment.py
.venv/Scripts/python.exe -m pip check
```

密钥在本机重新配置；不要把`.env`、密钥或机器写资格记录放进分发包。复制`.venv`不能代替安装，因为解释器和启动脚本可能保留原目录。首次安装需要访问包源；常规启动只检查本地版本。当前依赖锁不等于已经制作好的离线安装包。

环境检查通过后，双击根目录的`启动创作工作台.bat`。重复启动应打开已经运行的同一工作台。若旧窗口异常退出，而执行子进程仍持有实例资格，应等待或检查原进程；不要删除锁文件来强行接管。

需要选择作品父目录时，可以在PowerShell中指定已经存在的目录：

```powershell
.venv/Scripts/python.exe run_workbench.py --workspace "D:\我的作品"
```

以启动窗口显示的本机地址为准；默认端口被占用时，程序会选择其他可用端口。停止前先在页面暂停当前任务，等待当前执行结束，再关闭启动窗口。调用状态不明确时保留现场，按页面提供的恢复入口处理，不重复点击新的开始请求。

## 失败后的回退与恢复

新版本尚未接触数据时，可关闭该版本，回到保留的原安装目录，用原锁定环境启动原数据。若新版本已经写入数据库、作品格式或机器资格记录，不能仅换回旧程序继续写；必须先核对匹配版本的备份与受支持的恢复路径。

可写恢复通过工作台的受控恢复流程完成：核对归档与目标目录、复制和重新绑定、交接本机写资格、明确确认启用。整个过程中保留原来源。不要直接覆盖旧数据库、单独复制正文、删除机器记录或修改旧凭证。恢复后的初次打开不会自动续写；需要核对原草稿、批次位置和用量，再明确选择后续操作。

已经完成核验的恢复目录可通过现有启动器打开：

```powershell
.venv/Scripts/python.exe run_workbench.py --restore-dir "D:\恢复演练\目标作品"
```

该参数只打开原恢复数据库，不执行复制、认证或资格交接。未完成或缺失必要凭据的副本应被拒绝，不能改用普通数据目录来绕过。匹配版本回退、再次归档恢复和干净Windows安装的完整产品验收仍待完成；在这些证据齐备前，不将当前版本命名为稳定自用生产版。
