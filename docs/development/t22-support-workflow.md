# T2.2 身份声明与基线补充

2026-09-10。目标是让必要的新实体和未知初始值经过明确作者决定，再参与七类章节事实的计算和正式提交。完整表单交互属于紧接着的T2.3；本文记录已接入的后端和发布预览。

## 决定与存储

`chapter_fact_identity.py`复用现有实体目录形状，按种类精确解析ID、名称和别名。歧义返回全部候选，作者可明确选择已有实体，也可把本章称呼绑定到它；局部称呼不会静默变成全局别名。新人物、地点、物品的ID由book_id、持久review_id、local_key与种类派生。同章事实用`local:<key>`引用；实际准备时只替换实体引用字段，不改正文证据或状态值。

`chapter_fact_support.py`的`reviewed_fact_support_v1`包含identities和baselines两类明确作者决定。补充操作可初始化缺失的人物字段、位置、持有人/物品库存、数值计数、关系字段和名单。已有值一律拒绝覆盖，包括相同值；数量必须明确，名单人数由成员计算。声明地点/物品本身不会虚构位置、持有人或零库存。未知实体仍拒绝，重复台账和身份冲突保留为错误。

审核表新增nullable的support_json/support_sha256，不回填旧记录。更新补充使用现有审核revision CAS并验证当前草稿；最终确认哈希包含补充哈希。原事实卡、原始模型提案与提取来源保留。确认后补充不可修改；改稿后原补充与审核一起失效。

`PUT /api/fact-reviews/{review_id}/support`只接受support、expected_revision和明确的author_confirmed。新版dispatch把此操作置于现有机器作品锁/所有权及恢复边界；普通作品没有新补充的写入通行权。提交请求仍只有原来的IDs/CAS/幂等键，客户端不能提供准备结果或质量批准。

## 正式提交与重放

准备、质量核验、章节文档生成和冷读都调用`prepare_supported_fact_changes`。它先重算作者批准的身份/基线，再将七类事实应用于补齐后的状态；结果保留原始state_before哈希。质量层同时核验完整补充计划并独立重算后续事实变化，不把未知原状态伪装成已有基线。

人物仍在characters中；地点/物品声明以带类型的`reviewed_entity_declaration_v1`证据保存在现有events集合，供经过正式历史核验的上下文派生目录。普通事实不能使用这个保留事件类型冒充声明。没有第二个可写权威库。完整作者决定保存在prepared request及章节transition中，receipt绑定它们，下一章和新进程从这些正式资料重建。

没有补充的旧准备记录仍按原路径重放；带补充的transition增加明确的support及其哈希，旧版严格reader无法把它当作无补充记录静默接受。未改变B0对identity3的拒写边界，也未启用普通CLI或EA的新审核流程。

发布预览显示作者补充的身份、初始值与原因。此次也修复旧预览误读不存在的`payload/evidence`字段，改为实际`proposal/evidence_spans`，事实变化与原文引用现在可见。
