# T7.2：多次恢复的任务历史隔离

日期：2026-10-01。状态：内部重复任务历史隔离已验收；按同一用例最新结果合并，32 项新增检查、25 项原路径回归全部通过。完整恢复产品仍未交付。

## 实现与保留边界

首次恢复的 `workbench_restored_job_history` 保持原表、完整原行和原摘要。后续恢复新增 `workbench_restored_job_generations`，以恢复范围代次与任务 ID 为联合主键，每代保存当前导入任务的完整快照。已有快照不覆盖、不删除；原配置、结果、错误、事件、草稿与其他作品数据保持不变。所有导入任务再次失去执行资格，非终态任务取消，原终态保留。完整 SQL 变化仍从原归档预测，并与任务快照写入同事务提交。

后续任务意图和完成回执采用 v2，绑定原恢复来源证明及新 scope generation；首次 v1 意图、回执与四参数 SQL helper 保持兼容。继承的任务必须等于上一代已失效行，不能用本地重新计算摘要重新授予旧任务执行资格。离线归档核验沿记录的来源链重建每一代完整历史表，再检查本代当前任务仍是限定失效结果；不打开祖先目录或机器账本。新增历史表只有证明完整时才被归档分类，失去 scope 后也不能作为普通数据库启动。
