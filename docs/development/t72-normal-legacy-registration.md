# 正常旧书首次写入保护登记

日期：2026-10-02。阶段 D 内提前推进 T7.2 前置；组件内部验证通过，浏览器为 partial，完整恢复认证与格式升级尚未完成。

## 行为与范围

已校准的原始 Strict 1.0/2.0 作品可以在备份维护状态下，选择与当前整库、原书、来源、软件和配置一致且已实际离线核验的诊断归档，明确确认首次登记。服务器生成机器登记及作品凭证，保留身份、格式、正文和作者草稿。登记后必须重新备份；诊断归档始终 recoverable=false，不是升级许可。

实现为 workbench/legacy_registration.py，两个维护控制 API，以及诊断归档面板中的“旧书写入保护”入口。普通 BookOwnership.enroll 仍要求 reviewed 格式；兼容身份读取不会自动登记旧书。机器侧保存原归档与物理绑定的登记意图，四个持久化阶段允许明确续接同一动作。丢失机器记录、作品凭证或损坏原意图均拒绝重建；这不证明同时丢失全部历史证明后仍能识别旧资格。

取得维护许可后按机器、作品状态、Provider、数据库次序持锁。登记只写所有权控制文件，使用 owned_database_snapshot 的实际 SQLite 写入隔离事务和只读快照；不运行数据库初始化或普通启动恢复。重启维护期间数据库初始化可保持 pending，登记和原动作续接仍可核验实际既有整库。
