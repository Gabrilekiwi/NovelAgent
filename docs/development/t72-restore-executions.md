# T7.2：恢复执行隔离与新任务目录

日期：2026-09-15。状态：内部执行目录隔离与新任务目录准备已验收；目标活动资格和工作台接入尚未完成，恢复副本仍只读。

## 当前实现

`RestoreExecutionPreparation` 在已完成预算准备及旧任务隔离的实际恢复副本上继续。原归档、完整数据库限定变更、机器交接、根绑定、原消费与预算凭据重新核对后，生成独立执行策略。机器意图、容器策略和机器完成回执相互绑定；容器新增 `next-jobs` 空目录，其物理身份进入完成回执。原书籍与预算文件不迁移、不清零。

策略由归档的真实候选、事实提取、执行调用、辅助调用、提交意图、工作台任务根以及识别出的事务 manifest 建立禁止复用的目录/文件清单。归档后补入的原模型调用目录也纳入。候选/事实意图早于调用目录存在时，派生的原执行标识同样隔离。持久化 v2 的 journals/staging 同一 run 两个位置一起隔离。

执行观察入口、候选/事实执行与取消检查、模型调用、普通作品写入及正式提交入口均接入附加拒绝检查。历史 Store 的只读读取保持可用；新请求通过该检查仍需原有所有权、只读范围、预算和调用不确定性检查。该策略不会授予写权限。

外部旧任务目录通过祖先恢复容器定位实际只读scope，再核对实际book标识；不依赖调用者额外传入书籍根，也不从策略里的任意路径推断作品。策略、只读scope或作品身份缺失均拒绝。ModelCallRuntime额外要求恢复范围已启用，防止新标识绕过只读阶段直接创建调用凭据或发送请求。

策略文件使用固定暂存名、fsync 和不可覆盖发布；原意图缺失或变化时拒绝发布。完成状态缺少策略、物理任务目录被替换、完成凭据变化时不能自动修补。正常作品不使用恢复策略；已有机器登记和原写入口约束保留。

## 尚未完成的完整目标

目标仍是可写恢复，当前副本仍只读。此处创建的新目录需在最终目标限定范围/机器active资格转换中接入工作台，新候选/事实请求需证明使用新执行标识且不会重放旧请求。没有证明的旧直接执行/恢复入口必须继续检查；本步骤测试不能冒充完整旧计划失效或最终续写认证。

后续仍包括目标安全启用、重启零自动调用、确定性下一章、恢复来源再次备份、恢复向导、正常旧书升级/登记和整个A–F计划。未结算占用仍保留，真实Provider和真实作品写入未执行。

启用阶段的具体约束：机器active记录必须强制绑定恢复资格/执行策略，不能依赖可删除的容器标记来判断是否曾恢复；WorkBenchDatabase的只读判断、restore_scope API和中间件、app的任务根选择及claim_next需要共同支持目标限定的活动范围。启动仍禁止自动模型调用。新目录应从已保存的物理绑定取得，旧任务保持原隔离契约。恢复后的备份还须携带此次历史表、执行策略和来源凭据，不能因正常备份目前未识别这些内容而绕过检查。
