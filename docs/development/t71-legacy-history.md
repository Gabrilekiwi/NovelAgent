# T7.1 旧事务重叠历史核验

日期：2026-09-11。当前检查点：旧 v1 已保留事务及已知最终运行记录引用核验已接入备份预检；不是完整可恢复认证。T7.1 累计 122 项新增不同用例，完整 A–F 目标仍 active。

## 行为与依据

旧 D3 试验只接受一个已完成 v1 事务，并将每个事务的 after-image 与当前文件比较。连续多章正常覆盖同一 snapshot/状态文件后，这种比较会错误地拒绝较早章节。

`workbench/backup_history.py` 从已锁定的源清单读取所有发现的 v1 事务，核对格式、作品、允许根、稳定终态、目标索引、暂存内容、前像、候选结果及提交标记。每个读取文件仍与原清单的大小和 SHA-256 一致；不修改任何旧 manifest、marker、candidate 或目标。

核验器从当前目标哈希开始，以整份事务为单位逆向还原其逻辑前像，寻找覆盖全部事务的相容顺序。所有目标同时满足后像才能逆推，避免只证明每条文件链却漏掉跨文件冲突。重复哈希、无变化写入、独立目标及已完整回滚事务可参与核验；使用显式计算上限，超限拒绝，不能输出部分成功。顺序证明表示“存在与快照一致的事务顺序”，不声称重建了真实时间顺序，也不依赖机器时钟或目录名字排序。

已知 runs 目录中的最终运行记录进一步绑定其事务、run_id、committed/partial/state。只保留最终记录却丢失整个事务目录时不能通过。尚未证明所有其他格式、深层引用或全部运行目录均有覆盖，因此输出明确限定 `retained_v1_journals_and_known_final_run_references`，整包继续保持 `diagnostic`、`recoverable=false`。
