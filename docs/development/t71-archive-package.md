# T7.1 归档打包与来源证据

日期：2026-09-11。状态：诊断归档服务已验证；T7.1 仍未完成，没有认证可恢复备份。主目标仍为完整 A–F。

本页 103 项为归档组件检查点。后续已接旧事务重叠历史，累计 122 项；最新证据见 `t71-legacy-history.md` 与机器进度。

## 已实现的边界

`BackupArchiveService` 在维护捕获许可及已有来源锁内重算预览，将目标文件清单、整份数据库逻辑摘要、非秘密启动配置、磁盘代码/依赖锁哈希及作品机器所有权证据绑定到预览摘要。来源、数据库、配置或代码改变时，旧预览不能启动归档。新格式作品导出当前已核验所有权记录；旧格式明确记录尚未登记，均不自动转移所有权。

SQLite backup 写出独立整库副本，再把该副本和目标作品/必要任务根直接流式写入 ZIP。初版深层暂存复制触发了真实 Windows 路径长度失败，已去掉重复文件树，保留中文、空目录及逐文件哈希核验。整库包含其他登记作品的记录和未发布作者草稿，其他作品文件不随包复制；恢复禁用其他作品仍是 T7.2 必须实现的策略，当前元数据声明不等于已经禁用。

包内清单、包外清单与完成凭据交叉绑定。只读校验既核对 ZIP 每个成员，也将成员与已确认预览的每个源清单逐项比较。拒绝缺成员、额外成员、重复成员、路径越界、Windows 设备名/尾随点空格、文件目录冲突、加密/链接及损坏哈希。独立核验后再发布完成凭据，期间目录替换、元数据/代码变化均不能发布完成结果。配置只允许四个业务启动字段，不能通过可变对象追加密钥字段；`.env` 和已定义凭据名称被排除，但不声称能识别任意数据库/正文中的秘密。

`fingerprint_software` 记录规定产品代码树、资源和依赖锁的磁盘哈希，不导出源码内容。它不证明长时间运行进程已经加载的模块与磁盘一致；此项明确仍待认证。所有归档用途固定为 `diagnostic`，`recoverable=false`；没有调用方开关可以绕过认证。

## 验证证据

- 最终 `.tmp/stage-d-t71-archive-evidence-final.xml` / `.log`：32 项通过，53.86 秒，session 10699 exit 0。其中 29 项不同归档用例和 3 项既有来源锁用例。
- 更早整库/文件/持锁读取/归档组合 `.tmp/stage-d-t71-archive-stream-final.xml`：44 项通过；包含旧 17 项归档用例，不能重复累计。
- 真实子进程在 ZIP 已写完、完成凭据发布前 `os._exit(23)`；父进程确认文件保留、没有完成凭据、只读核验拒绝、新实例维护状态为 interrupted。
- 实际 reviewed 合成作品及 legacy 合成作品归档均通过，未发布草稿与整库第二作品记录保留；无真实书写入，无 Provider 调用。
- 故意修改 ZIP 与完成凭据使哈希重新一致、但漏掉预览中的作者笔记，仍被范围核验拒绝。
