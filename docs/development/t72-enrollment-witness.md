# T7.2 基础：持久登记凭证与中断续接

日期：2026-09-14。内部登记协议和受支持写入口的缺账本拒绝已经通过专项测试；正常用户登记/升级入口及完整恢复交接仍未完成。浏览器预览验证通过，最终勾选发布被自动审批拒绝，整条浏览器发布路径记为部分验证。

## 变化

原 `BookOwnership.enroll` 只有机器目录中的一条记录。删除该记录后，一部分兼容旧书的输出入口会把作品当作从未登记。现在首次显式登记创建 `machine_book_ownership_v2` 以及作品内的 `.novelagent/write-registration.json`。作品凭证含随机登记编号、book_id、初始物理绑定摘要和自身摘要；机器记录关联同一登记编号及凭证摘要。

正常写入不自动创建、修复或迁移凭证。`book_output_write_lock` 和 `BookOwnership.require` 均检查凭证：有作品凭证但机器记录丢失时拒绝；v2 缺作品凭证或凭证不匹配也拒绝；作品身份丢失而凭证仍在时，在定位所属作品期间拒绝。复制到新目录、换数据库或选择空机器目录不会授予资格。

显式首次登记按以下顺序持机器锁和实际数据库事务执行：

1. 核验已升级作品的真实身份/历史和当前数据库物理登记。
2. 持久写入 `enrolling` 机器记录，绑定唯一登记编号、原始绑定和预期凭证摘要。
3. 创建不可变作品凭证。
4. 重验锁、当前机器记录、作品凭证和数据库物理登记，再把机器记录改为 `active`。

普通写入口在 `enrolling` 时停写。重复显式登记可续接同一个未完成的登记，只能使用原数据库、书根和登记编号；不会产生第二个登记。已经 active 的凭证缺失不会被补建。旧 v1 active 记录仅在原绑定完全一致的显式登记中升级；暂停或错绑记录不能迁移。

这里的凭证是本机协作协议的持久证据，不是签名防伪。旧 v1 记录与所有本地证明同时丢失、任意旧程序、恶意删除或改写所有证明的情形不能据此宣称已经解决。未登记旧书仍保留原兼容行为。后续恢复交接需要核对归档凭证与当前机器代际，不能仅改路径或重算摘要。
