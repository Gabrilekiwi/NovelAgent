复用七类领域状态与受管块编解码，在项目 `追踪/已审核事实.md` 保存明确标为试验格式的当前状态。人工原文保持原样；首次接入必须显式确认某个章节边界的基线、来源修订和身份映射，不能把 supporting 或缺失字段自动提升成确认基线。生产格式和入口隔离须等 D2 验证。

规则：

1. 初始基线是作者确认的接入时刻状态；当前状态是在此之后正式确认的章节变化。角色目标、关系、成员、位置、库存、计数和事件按已有七类契约推进，身份声明另由 T2.2 处理。
2. 人工来源修订覆盖追踪、设定文件的成员集合与受管块以外的内容。候选只规范化文件末尾 CR/LF，避免首次插入受管块产生的分隔换行误报；其余内容和文件增加、删除、修改均使绑定过期。正式准备还须由 T3.2 完整 read-set 约束，不以这个人工内容指纹替代文件级校验。
3. 来源变化后停止读取为可提交当前状态。保留旧当前值的决定必须绑定作品、原绑定、新来源、当前状态版本和具体差异；该决定持久化，不能是进程里的布尔开关。需要改变当前值时保留冲突，后续显式更正流程处理，不从任意自然语言猜值。
4. 准备结果绑定正文、完整事实决定、来源修订和受管资料版本。即使改稿后又改回相同文字，修订号变化也使旧决定失效。
5. 清缓存重建只读取项目资料。SQLite 和 Memory 投影不成为第二套状态权威。校验和只证明内容完整性，正式提交来源仍须由 T3.2 事务与凭证证明。
