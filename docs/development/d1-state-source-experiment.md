## D1最终决议

1. **来源分工。** 人工接入基线及其原文保留。项目受管资料保存经确认推进的七类当前状态；现有Memory与SQLite都不能替代这份状态。运行视图是纯数据接口，由来源loader验证文件、人工修订、静态引用后构建；消费端再核对身份、章号、read-set成员、源文件哈希、semantic绑定及payload完整性。消费端的哈希不是独立读盘或正式提交证明。
2. **时间与字段。** 位置由`locations`账本推进；人物记录若已有`location/location_id/current_location`镜像，位置事实由程序同步更新并记录派生字段，已有矛盾则拒绝。普通character_state不能另写位置。接入基线的`story_project_standard`来源等级保留，经确认的章节事件推进当前值，不将人工来源降成model_inference。场景地点不从任意人物位置猜测。
3. **冲突与失效。** 保留当前值的作者决定绑定具体旧头、新人工来源及差异，持久化后可冷读；再次编辑来源使旧决定失效。正文修订、事实决定或来源变化均需要重新确认，改后改回文字也不复用旧决定。已确认静态片段所在文件后改时，单纯“保留当前值”不能顺便确认新静态资料。
4. **当前输入与静态资料。** 当前人物/位置视图不合并旧动态语义或缓存。静态人物字段按明确姓名/别名的双向唯一匹配补缺，保留已有确认值；歧义拒绝，未映射字段有诊断。保留结构化世界、约束、空间spaces/connections、待续线索和伏笔，伏笔显式进入最终prompt。尚未结构化但需要的设定使用接入时明确确认、绑定文件和原文的静态片段，不能全量恢复旧动态tracking文本，也不能声称已自动覆盖任意旧书的全部资料。
5. **启用边界。** `ChapterCandidateContextBuilder`仅在内部显式注入loader时启用新视图；正常CLI/工作台不会发现试验文件。试验格式已经演进为`d1-reviewed-state-experiment-2`，不承诺与上一份试验数据兼容。D2决定正式格式、旧程序拒写及任务版本边界；T3.2完成正式事务/凭证/索引，T2.2完成真实接入的身份及静态资料覆盖预检。真实书接入仍需后续T7.1备份和真实Strict资格。
