# T7.2 恢复交接后的原消费证据保留

日期：2026-09-14。状态：内部消费证据保留已验收；预算合并尚未完成，恢复副本仍只读。

恢复包可能早于最新模型调用。机器写资格的 generation 只说明所有权，不能证明作品的章节或消费未变化。因此，不能用归档中的旧预算替换当前消费，也不能因原目录不可用而采用零消费。

`workbench/restore_usage.py` 新增内部 `RestoreUsage` 服务。它只接受已经完成撤销且尚未回退的真实恢复交接，核对同一机器记录、原实际作品与数据库绑定、v2 见证，以及原有 Provider 锁；锁丢失时不会创建替代目录。机器锁、作品持久化锁、Provider 边界和数据库写屏障覆盖来源读取。

保存意图先落盘，随后把原作品身份、登记见证、冻结预算、模型调用和执行来源的原始文件保存为机器目录内的不可覆盖内容对象，最后写完成回执。两次清单及完成前复读检查来源变化，完成凭据绑定原交接和完整文件清单。只在原意图和来源仍匹配时显式续接，不能重新取样覆盖中断状态。

完成读取不访问原书或初始化预算 store，而是从已保存字节重新执行既有离线预算和调用核验。文件缺失、内容变化或仅修改汇总回执均不能变成成功；原始 bytes 和使用汇总必须一致。未结算占用和主动时间未知状态原样保留。

原作品或数据库不可用且尚未保存时，持久记录 `usage_state=unknown`，`usage=null`。这不代表零次调用或零费用。来源恢复后可以显式保存，原未知观察记录仍保留。完成回退后，旧用量凭据不能再作为当前交接的准备依据。
